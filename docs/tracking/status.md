## 남은 일 (우선순위 순)

1. **쓰기 경로 봉인** — 후속 봉인 작업(운영 DB 트리거·RLS 변경은 대표 승인 필요)
   - 매출·지출 수정·삭제를 본인 등록분 + 해당 사업부 리더 + 관리자로 제한한다.
   - `paid`·`canceled` 삭제를 막는다. 프로젝트 삭제로 인한 연쇄 삭제와 법인카드 연결 변경 경로도 포함한다.
   - `paid`→`planned` 되돌리기를 관리자만 할 수 있게 한다.
   - 금액·상태·사업부 변경을 기록한다.
2. **계정 승인** — 가입 후 관리자 승인 전에는 데이터 접근을 차단한다. 막힌 이유: RLS 변경은 운영 DB 변경(대표 승인)이고, reactstudio.kr 공개 페이지와 관리자 가입 경로 영향 검증이 필요하다.
   - `app_users` 비로그인 INSERT와 본인 역할 변경을 막는다.
   - 퇴사자·승인 대기자를 서버 라우트와 RLS에서 차단한다.
3. **인증 없는 라우트 약 24개와 서버 권한 키 라우트 정리** — 막힌 이유: 코드 변경과 운영 배포 승인, 운영 Vercel의 `CRON_SECRET` 설정 권한이 필요하다.
   - 로그인·재직·역할 확인을 공통 가드로 넣는다.
   - `...body` 통째 update(`financial-entries/[id]`, `tasks/[id]`, `meeting-rooms/[id]`, `vehicles/[id]`)를 허용 컬럼으로 바꾼다.

   - `CRON_SECRET`을 설정하고 알림 크론을 헤더 방식으로 통일한다.
4. **최소 회귀 테스트** — 1~3에서 고친 API의 401·403·허용 외 컬럼 거부. 막힌 이유: 테스트 도구가 아직 없고, 테스트 계정 정보를 커밋 없이 주입할 방법(환경변수)을 먼저 정해야 한다.
5. **운영·레포 마이그레이션 기준선 맞추기** — 운영 약 130 vs 레포 31. 막힌 이유: 운영 스키마 덤프와 빈 DB 재구성 대조가 필요하다.
