## 쓰이지 않는 기능 (정리 대상, 대표 확정)

회사 밖 사람은 ERP에 로그인하지 않는다.
아래 기능은 데이터가 0건이다. 1차 브랜치에서 서버는 누구에게나 403을 주고 메뉴에서 뺐다. 코드와 테이블은 남아 있다.
- 아티스트 화면(`/artist`, `artist-dashboard`), `api/artist/*`, `artist`·`viewer` 역할 분기
- 프로젝트를 아티스트·파트너에게 공개하는 설정(`visible_to_partner`, `projects/[id]/share-settings`)과 아티스트 제안 응답(`artist_response`)
- 파트너 수익배분 정산(`api/partner-settlements*`, `partner_settlements` 0건). 정산 화면(`SettlementView`)의 파트너 하위 탭 2개(프로젝트 분배, 정산 목록)는 숨겼다. 정산 화면의 개요·미수금 탭은 주 재무 화면이라 유지한다.

## 남은 일 (순서대로)

1. **1차 운영 반영** — 순서를 바꾸지 않는다.
   1. 미리보기 배포(스위치 꺼짐, 현재 운영 DB)에서 역할별 `e2e-` 계정으로 화면 E2E와 `npm run test:api` 실행. 워커 디제스트·월 손익·기한 초과 경보가 달라지지 않았는지 확인.
   2. **대표 승인 ①**: `main` 반영(`ERP_AUDIT_V2` 꺼짐)과 운영 Vercel `CRON_SECRET` 설정을 같은 시점에. 다음 크론 성공 확인.
   3. reactstudio.kr 봉인 대비 변경(그 저장소 커밋 `0465a9e`) 운영 배포(그 저장소 승인 별도). 끝나지 않으면 ②로 가지 않는다.
   4. **대표 승인 ②**: `supabase/apply/20260925_seal_apply.sql` 운영 적용(데이터 보정 1건 포함) → 곧바로 `ERP_AUDIT_V2=1` 재배포 → 외부 사용자 조회·reactstudio.kr 관리 화면·ERP 로그인·출퇴근·푸시·변경 기록 확인. 문제 시 되돌리기 스크립트.
   5. 운영에 만든 `e2e-` 계정 퇴사 처리.
2. **최소 회귀 테스트 보강** — 막힌 이유: 없음(1차 반영 뒤 이어서 한다). 봉인 5개 밖 테이블은 봉인 SQL 7절로 비재직 계정 차단까지는 준비되었다(`tests/db/seal-outside.test.ts`). 재직 직원 사이의 역할·사업부별 RLS(`partners`·`contracts` 등 `authenticated` 전권)는 남은 일이다.
3. **재무 스키마 추가(추가만, 2차)** — 막힌 이유: 운영 DB 변경(대표 승인)이고, 인건비 category 표준값은 대표가 정해야 한다.
   - 결제형 매출 일 합계 칸 9개 + 멱등 키
   - 인건비 합계 category 표준값
   - `business_units` 법인 칸
4. **전사 연결(2·3차)** — 외부 앱 프로젝트의 ERP 번호 연결, 동일인 연결표, 재무 통제 콘솔(DEV 브랜치 `feat/unified-finance-control-dev`) 운영 배포, 지급예정 동기화, Clobe 자동 대사와 매일 점검. 막힌 이유: 1의 권한 봉인이 운영에 먼저 반영되어야 한다.
5. **쓰이지 않는 기능 정리** — 위 목록의 화면·라우트 코드를 제거한다. 막힌 이유: 코드 제거의 운영 배포 승인과, 테이블 삭제에 대한 별도 대표 승인이 필요하다.
6. **데이터 품질** — 막힌 이유: 운영 데이터 일괄 수정이라 대표 승인이 필요하고, 입금일·PM 같은 값은 담당자 확인이 있어야 채울 수 있다.

   - `pm_id`가 없는 프로젝트
   - 자유 입력 category(약 200종)
   - 지급 방식이 비어 있는 92건

## 대표 결정 대기

- **1차 권장안 확인(최종 승인 단계)**: 이 셋은 권장안으로 구현되어 있다. 대표가 다르게 정하면 `permissions.ts`·봉인 SQL·문서를 함께 바꾼다.
