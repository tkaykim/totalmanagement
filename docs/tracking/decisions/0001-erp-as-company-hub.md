# 0001. ERP를 전사 프로젝트·재무 허브로 쓴다

## 배경
- 사업부마다 앱과 DB가 따로 있어 할일·매출·지출·담당자가 흩어져 있었다(deetz, grigo-artist, modoo, moveit 등).
- 대표가 전사 현황을 한 곳에서 볼 수 없었다.
- ERP에는 이미 프로젝트 812건, 재무 665건, 할일 723건이 사업부 코드와 외래키로 묶여 있었다.

## 결정
- 새 통합 시스템을 만들지 않는다.
- 이 ERP의 `projects.id`를 전사 프로젝트 키로 쓰고, 재무 통합 읽기모델과 할일 정본도 여기에 둔다.
- 먼저 쓰기 경로 보안을 봉인하는 조건으로 개편한다.

## 검토한 대안
- **새 통합 DB·앱을 만든다**: 다섯 번째 "프로젝트" 테이블이 생겨 연결이 더 꼬인다. 기존 데이터 이전 비용이 크다.
- **허브 DB(orchestrator)의 `business_projects`를 정본으로 쓴다**: 재무·할일과 외래키로 연결되어 있지 않고, 직원이 입력하는 화면이 없다.

## 결과
- ERP의 스키마·enum은 이제 전사 계약이다. 기존 값을 바꾸거나 지울 수 없고 추가만 가능하다.
- 권한 구멍(가입 즉시 사용, 전원 수정 가능)을 먼저 막지 않으면 허브 승격을 진행할 수 없다.
- ERP 사업부 코드가 없는 사업(moveit, udong 등)은 당분간 허브 쪽 목록에 남는다.
