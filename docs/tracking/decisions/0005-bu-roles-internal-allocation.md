# 0005. 사업부 역할 분리와 내부배부

## 배경
- deetz 채널 콘텐츠를 REACT가 촬영하고, 그 안에 GRIGO 전속 아티스트가 출연하는 식의 교차 프로젝트가 생겼다.
- 한 칸(`bu_code`)으로는 누가 매출 주인이고 누가 제작했는지 표현할 수 없었다.
- 같은 매출이 여러 사업부에 중복 집계될 위험이 있었다.

## 결정
- `projects.bu_code`는 외부 손익의 주인 사업부만 뜻한다.
- 브랜드·제작·전속 관리 역할은 `brand_bu_code`, `delivery_bu_code`, `artist_management_bu_code`로 나눈다.
- 사업부 사이 제작비는 `financial_entries.entry_scope='internal_allocation'` + `counterparty_bu_code`로 적는다.
- 사업부 관리손익에는 내부배부를 포함하고, 전사 연결손익에서는 뺀다.

## 검토한 대안
- **프로젝트를 사업부별로 쪼갠다**: 같은 일이 여러 프로젝트로 흩어져 전사 프로젝트 키 역할을 못 한다.
- **외부 매출을 역할별로 나눠 적는다**: 세금계산서 한 장이 여러 행으로 쪼개져 증빙 대사가 불가능해진다.

## 결과
- 모든 손익 집계는 `entry_scope`를 반드시 읽어야 한다. 읽지 않는 집계(현재 main 화면)는 연결손익을 과대 계상한다.
- 스키마는 운영 DB에 2026-08-10 적용됐고, 화면 반영은 대기 중이다.
